02 — Stack

Tecnologias, por camada

A escolha da ferramenta decorre do problema. Estas são as que domino a ponto de utilizar sem consulta à documentação.

01

Linguagens

A base de tudo. Tipagem estática em projetos de ciclo longo; Python quando o objeto é dado.

TypeScript

JavaScript com verificação de tipos: aponta o erro antes de ele chegar em produção.

JavaScript

A linguagem que roda no navegador. Toda interação da tela passa por ela.

Python

Usada para automação de tarefas e tratamento de grandes volumes de dados.

SQL

A linguagem com que se pergunta ao banco de dados o que ele guarda.

02

Interface

O que o usuário vê e toca. Prioridade para clareza, acessibilidade e desempenho em conexão limitada.

React

Mantém a tela sempre sincronizada com os dados, sem recarregar a página.

Next.js

Entrega páginas prontas do servidor: abrem rápido e são lidas pelo Google.

Tailwind

Padroniza o visual do sistema e reduz o tempo de ajuste de layout.

Vite

Recarrega o projeto em milissegundos durante o desenvolvimento.

03

Servidor

A parte invisível: onde as regras de negócio são aplicadas e os dados, protegidos.

Node.js

Executa JavaScript no servidor — a mesma linguagem dos dois lados do sistema.

Express

Estrutura enxuta para construir a API que conecta a tela ao banco.

Postman

Testa e documenta cada rota da API antes de ela entrar no ar.

04

Dados

Onde a informação vive. Modelagem antes da implementação e migrações versionadas.

PostgreSQL

Banco de dados de código aberto, referência em consistência e confiabilidade.

Prisma

Camada de acesso ao banco que impede consultas inválidas ainda na escrita do código.

Redis

Guarda respostas na memória para que consultas repetidas sejam instantâneas.

05

Infraestrutura

Onde o sistema roda e como ele chega ao ar. Ambiente reproduzível, publicação automatizada.

Docker

Empacota a aplicação para que rode igual em qualquer servidor, sem surpresa.

AWS

Servidores, armazenamento e banco sob demanda, com custo proporcional ao uso.

Vercel

Hospedagem otimizada para Next.js, com publicação automática a cada versão.

NGINX

Distribui as requisições que chegam e protege a aplicação da exposição direta.

Linux

O sistema operacional dos servidores em que a aplicação é publicada.

GitHub Actions

Roda os testes e publica a nova versão sozinho, a cada alteração aprovada.

06

Processo

Como o trabalho é registrado e revisado. Histórico legível do primeiro ao último dia.

Git

Controle de versão: cada alteração fica registrada e pode ser revertida.

GitHub

Onde o repositório fica hospedado e o cliente acompanha o andamento.

Figma

Desenho da interface aprovado antes de qualquer linha de código.

03 — Método

Condução do projeto, etapa a etapa

Cinco fases, cada uma com entregável definido e requisito correspondente da parte contratante.

01

Descoberta

Reunião de trinta a sessenta minutos destinada à compreensão do problema de negócio, anterior a qualquer definição técnica. O objetivo é estabelecer quem utiliza o sistema, com que frequência e qual o impacto de sua indisponibilidade.

Entregável
Delimitação de escopo e proposta comercial com prazo e valor
Requisito
Acesso a quem conhece o processo atual
02

Arquitetura

Modelagem de dados, definição do contrato da API e justificativa documentada das escolhas de tecnologia. É a etapa em que decisões de alto custo ainda podem ser revistas sem impacto.

Entregável
Diagrama de dados, contrato de API e stack definida
Requisito
Validação formal das regras de negócio
03

Desenvolvimento

Ciclos semanais. Ao término de cada ciclo, uma versão navegável é publicada em ambiente de homologação — o sistema em execução, não representação estática.

Entregável
Ambiente de homologação atualizado semanalmente
Requisito
Retorno em até dois dias úteis por ciclo
04

Publicação

Implantação em infraestrutura de titularidade do cliente, com variáveis de ambiente documentadas, rotina de backup configurada e pipeline de publicação automatizado.

Entregável
Sistema em produção e repositório transferido
Requisito
Domínio e contas de infraestrutura em nome do cliente
05

Acompanhamento

Trinta dias de correção de defeitos sem custo adicional a contar da entrega. Encerrado o período, a manutenção pode ser contratada em regime mensal ou por demanda.

Entregável
Garantia de trinta dias sobre defeitos
Requisito
Canal definido para registro de ocorrências

06 — Dúvidas frequentes

Questões recorrentes na contratação

As dúvidas que se apresentam em toda primeira conversa, respondidas previamente.

01Como é definido o orçamento?
Escopos bem delimitados são orçados por valor fixo, com prazo e entregáveis descritos em contrato. Quando o escopo permanece aberto ou o trabalho é de manutenção contínua, a cobrança é por hora, acompanhada de relatório das atividades executadas. A proposta é emitida após a reunião de descoberta.
02Qual é o prazo usual de execução?
Varia conforme o escopo. Como referência: uma página institucional demanda de uma a duas semanas; um sistema com autenticação, banco de dados e painel administrativo, de quatro a oito semanas. O cronograma consta da proposta, com as datas de cada ciclo, e o progresso é verificável semanalmente em ambiente de homologação.
03A quem pertence o código ao final?
Ao contratante. O repositório é transferido para a conta da empresa na entrega, com o histórico completo de versionamento. Não são utilizadas plataformas proprietárias que vinculem o projeto ao fornecedor: havendo troca de desenvolvedor, o sucessor acessa o repositório e dá continuidade.
04Quem custeia e administra a infraestrutura?
As contas de infraestrutura — domínio, servidor, banco de dados e correio eletrônico — permanecem em nome e sob titularidade do contratante, com a configuração realizada em conjunto. Assim o custo é transparente e o acesso não depende do fornecedor. A administração pode ser assumida por mim mediante contrato de manutenção.
05Há suporte após a entrega?
Sim. Toda entrega conta com trinta dias de garantia sobre defeitos: itens previstos em escopo que não operem conforme o acordado são corrigidos sem custo adicional. Encerrado o período, é possível contratar manutenção mensal ou atendimento por demanda, sempre com condições definidas previamente.
06Há atuação junto a equipes internas?
Sim, e é prática frequente. Integro-me ao repositório e às cerimônias da equipe, observo o padrão de código vigente e submeto alterações por pull request, como qualquer outro integrante. A origem em consultoria me habituou a produzir dentro do processo do cliente, e não a substituí-lo.
07Como se formalizam contrato e pagamento?
Por contrato de prestação de serviços, com escopo, prazo, valor e regras de alteração descritos. O pagamento é vinculado a etapas — parcela inicial e parcela na entrega — sem antecipação integral. Emite-se nota fiscal.
08O atendimento é presencial?
O regime é remoto, para todo o território nacional, modalidade em que se desenvolve a maior parte dos projetos. As reuniões ocorrem por videoconferência e a comunicação assíncrona se dá no canal já utilizado pelo cliente. Atendimento presencial pontual no Rio Grande do Sul é passível de combinação.
